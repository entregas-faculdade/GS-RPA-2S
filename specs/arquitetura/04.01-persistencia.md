# 1. Propósito
Descreve `triage.storage`: a única camada que toca o banco SQLite local. Dá ao robô idempotência por pedido, fila de
revisão humana, feedback 👍/👎 e registro de execuções. Só texto **anonimizado** chega ao banco
([[003-seguranca-sem-autenticacao]]).

# 2. Stack e Ferramentas
- `sqlite3` da biblioteca padrão, importado **só** em `storage/schema.py`; nenhum outro pacote o importa.
- O arquivo `.db` é local e fora do Git ([[01.01-estrutura-do-projeto]]); o caminho vem do chamador.
- Todo SQL usa parâmetros vinculados (`?`); o DDL é literal. Cada operação abre uma conexão curta, com
  `PRAGMA foreign_keys=ON`, confirma a transação ao fim do bloco e fecha a conexão.

# 3. Diagramas / Estruturas
```
src/triage/storage/
  schema.py      SCHEMA (DDL), init_db(path), session(path), StorageError
  hashing.py     normalize_text(), request_hash()
  repository.py  Repository, RequestRecord, ReviewItem
```

**Tabelas** (nomes em inglês):

| Tabela | Colunas |
|---|---|
| `requests` | `hash` PK, `anonymized_text`, `category`, `confidence`, `status`, `review_reason`, `created_at` |
| `review_queue` | `id` PK, `request_hash` FK, `reason`, `created_at`, `resolved` (0/1), `resolution_note` |
| `feedback` | `id` PK, `request_hash` FK, `rating` (`up`/`down`), `created_at` |
| `runs` | `id` PK, `started_at`, `finished_at`, `totals_json` |

`status` ∈ `answered`, `queued_for_review`, `rejected`, garantido por `CHECK`. Datas em ISO-8601, UTC.

**Hash do pedido.** `request_hash(anonymized_text)` é o SHA-256 (hex) do texto normalizado: Unicode NFC, espaços
colapsados e `casefold`. É a chave de idempotência.

**Contrato de `Repository(db_path)`** (o construtor chama `init_db`, que cria o diretório e as tabelas que faltarem e
pode ser repetida sem perda de dados):

| Método | Comportamento |
|---|---|
| `already_processed(request_hash) -> bool` | o hash já está em `requests` |
| `save_request(record: RequestRecord, *, anonymized: bool)` | exige `anonymized=True` (senão `ValueError`) e `status` válido (senão `ValueError`); o mesmo hash gravado de novo é ignorado, nunca erro |
| `enqueue_review(request_hash, reason) -> int` | insere na fila e devolve o id |
| `pending_reviews() -> list[ReviewItem]` | itens com `resolved = 0`, por id |
| `resolve_review(review_id, note) -> bool` | `False` se o id não existe ou já estava resolvido |
| `add_feedback(request_hash, rating)` | `rating` diferente de `up`/`down` levanta `ValueError` |
| `start_run() -> int` / `finish_run(run_id, totals: dict)` | abre e fecha o registro de execução; `totals` vai como JSON |

`RequestRecord` agrupa `request_hash`, `anonymized_text`, `status` e, opcionais, `category`, `confidence` e
`review_reason`; quem grava monta o registro (a assinatura de sete parâmetros soltos violaria o limite de quatro).

**Erros.** Falha de I/O ou do SQLite (inclusive violação de chave estrangeira, como enfileirar ou avaliar um hash
que não existe) vira `StorageError`, com a causa preservada; o log traz só o nome do erro, nunca o texto do pedido.
O pipeline decide o caminho seguro.
