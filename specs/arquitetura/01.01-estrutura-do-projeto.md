# 1. Propósito
Descreve o esqueleto do projeto: onde cada pacote vive, como a configuração e o log funcionam e como se roda e se
verifica o código. É o contrato que as demais specs do núcleo assumem.

# 2. Stack e Ferramentas
- **Layout `src/`:** o código vive em `src/triage/`; `pytest.ini` define `pythonpath = src` e `testpaths = tests`.
  `run.py` insere `src/` no `sys.path` para rodar sem instalar o pacote.
- **Dependências:** `requirements.txt` (execução: `scikit-learn`, `pandas`, `requests`, `python-dotenv`,
  `streamlit`) e `requirements-dev.txt` (`-r requirements.txt`, `pytest`, `ruff`, `nbformat`, `jupyter`), todas com
  versão exata (`==`). Verificado apenas em Python 3.14.0.
- **Ambiente:** `.env` (fora do Git) alimenta a configuração; `.env.example` lista as chaves sem valor secreto.
  `.gitignore` cobre `.env*` (exceto `.env.example`), `output/`, `*.db`, `.venv/`, `__pycache__/` e
  `.ipynb_checkpoints/`.
- **Comandos:** `pip install -r requirements-dev.txt` · `python run.py` · `python -m pytest -q` ·
  `python -m ruff check run.py src tests`.

# 3. Diagramas / Estruturas
```
run.py                      ponto de entrada (argparse)
src/triage/
  config.py                 Settings e load_settings()
  logging_setup.py          configure_logging() / shutdown_logging()
  ingestion/ privacy/ classification/ automation/ storage/ pipeline/ interface/
tests/                      testes (espelham src/)
data/  notebooks/           dados de exemplo e notebooks (com .gitkeep)
output/                     logs e relatórios gerados (ignorado pelo Git)
```
Os subpacotes são o mapa de pacotes do [[00-contexto]]; cada um tem `__init__.py` com docstring em português.

**Configuração.** `load_settings(dotenv_path=Path(".env"))` devolve um `Settings` imutável (`dataclass(frozen=True)`) com
`llm_enabled` (padrão `False`; aceita `1/true/yes/on`), `llm_base_url`, `llm_model`, `llm_api_key`, `log_level`
(padrão `INFO`) e `output_dir` (fixo em `output`; `run.py` o sobrescreve por `--output`). A ausência do `.env` não é
erro. É o único ponto de leitura de configuração.

**Log.** `configure_logging(settings)` grava em `<output_dir>/logs/run.log` e no console, no formato
`timestamp nível módulo mensagem`; nível inválido cai em `INFO`. Um filtro troca a chave de API por `***` se ela
aparecer numa mensagem. `shutdown_logging()` fecha os handlers. Texto bruto do cidadão e a chave nunca são logados
([[003-seguranca-sem-autenticacao]]).

**`run.py`.** Aceita `--input` (padrão `data/samples`) e `--output` (padrão `output`). Pasta de entrada inexistente:
log de erro e código de saída `2`, sem traceback. Pasta existente: código `0`.
