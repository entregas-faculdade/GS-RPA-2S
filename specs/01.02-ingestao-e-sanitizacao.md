# 1. Visão Geral
Etapa 1 do fluxo ([[00-fundacao-tecnologica]]), em `triage.ingestion`. `read_folder(pasta)` devolve
`(requests, rejections)`: os pedidos válidos já sanitizados (`Request(id, text, source)`) e os descartes com motivo
(`Rejection(source, reason)`), ambos `dataclass(frozen=True)`. Um arquivo ou registro ruim vira rejeição; nunca
interrompe a leitura dos demais. O texto devolvido ainda **não** passou pela anonimização de PII.

# 2. Regras de Negócio

## 2.1 Formatos
- **`.txt`:** um pedido por arquivo; o `id` é o nome do arquivo sem extensão.
- **`.csv`:** colunas `id,text`, uma linha por pedido (campo com quebra de linha entre aspas é aceito). Sem coluna `text`,
  o arquivo inteiro é rejeitado.
- **`.json`:** lista de objetos `{"id", "text"}` ou um objeto único. `id` pode ser string ou inteiro (guardado como
  string); `text` precisa ser string. Item que não é objeto é rejeitado sem afetar os demais.
- Leitura em UTF-8 estrito, aceitando o BOM (`utf-8-sig`). A extensão é comparada sem diferenciar maiúsculas.
- `source` é o nome do arquivo e, em csv/json com vários pedidos, `arquivo#posição` (a partir de 1).

## 2.2 Pasta
- `read_folder` não é recursivo, ignora subpastas e registra `WARNING` para cada extensão não suportada.
- Pasta inexistente levanta `FileNotFoundError`; quem decide o que fazer é o chamador.

## 2.3 Motivos de rejeição (`REASON_*` em `models.py`)
| Código | Quando |
|---|---|
| `empty_file` | arquivo só com espaço, csv sem linhas ou json `[]` |
| `unreadable_encoding` | bytes que não decodificam como UTF-8 |
| `unreadable_file` | erro de sistema ao abrir/ler (`OSError`) |
| `invalid_json` | JSON malformado, aninhamento que estoura a recursão, raiz que não é objeto/lista ou item que não é objeto |
| `invalid_csv` | erro do parser csv (ex.: campo acima do limite do parser) |
| `missing_text_column` | csv sem coluna `text` |
| `missing_text` | item json sem `text` string |
| `too_large` | texto bruto com mais de `MAX_TEXT_LENGTH` (2000) caracteres |
| `empty_id` | `id` vazio ou só espaço |
| `text_too_short` | texto, depois de sanitizado, com menos de `MIN_TEXT_LENGTH` (3) caracteres |

## 2.4 Sanitização (`sanitize(text)`)
O limite de tamanho vale para o texto bruto e é checado primeiro (`TextTooLargeError`). Depois, nesta ordem:
normalização Unicode NFKC; remoção de caracteres de controle, exceto quebra de linha e tab; remoção de comentários
HTML; remoção de `<script>` e `<style>` **com o conteúdo** (sem fechamento, vai até o fim do texto); remoção das demais
tags, só o marcador (`<` seguido de letra, `/` ou `!`, para preservar `a < b`); troca por espaço de `;--` e
`' OR '1'='1` (sem diferenciar maiúsculas); colapso de espaços e de 3+ quebras de linha em 2. O pipeline nunca monta SQL
por concatenação; essa troca é uma neutralização adicional.

`validate(request)` devolve a `Rejection` (`empty_id`, `text_too_short`) ou `None`.

## 2.5 Log
O log de ingestão traz só nome de arquivo, posição e código do motivo. O texto do pedido e o `id` nunca são logados
([[003-seguranca-sem-autenticacao]]).
